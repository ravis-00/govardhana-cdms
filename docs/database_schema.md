## 1. General Rules

1. Row 1 of every operational Google Sheet contains column headers.
2. Header names use lowercase `snake_case` wherever practical.
3. Apps Script maps values using header names rather than fixed column positions.
4. IDs are generated by Apps Script unless explicitly documented otherwise.
5. IDs must not depend on spreadsheet formulas.
6. Cattle IDs, tag numbers, receipt numbers and bill numbers are stored as text.
7. Display dates use `DD-MM-YYYY`.
8. API dates use `YYYY-MM-DD`.
9. Timestamps contain date and time.
10. Historical lifecycle events must not be overwritten.
11. Cancelled operational and financial transactions remain stored for audit.
12. Cancelled transactions are excluded from active financial reports.
13. Financial rates and calculated amounts are stored as transaction snapshots.
14. Header-and-line transactions use separate parent and item sheets.
15. Financial calculations are independently validated by the Apps Script backend.
16. Generated IDs and bill numbers are created while holding an Apps Script lock.
17. Created-by and created-at values are preserved during Update.
18. Updated-by and updated-at values are refreshed during Update.
19. Backend validation is authoritative.
20. Blank optional numeric fields are interpreted as zero where documented.

## 2. `cattle_master`

### Purpose

Permanent master record for every cattle.

### Primary Key

`internal_id`

### Important Rule

`internal_id` is permanent. `tag_number` contains only the current active ear tag. Historical tag changes are stored in `tag_history`.

### Main Columns

| Column | Purpose |
|---|---|
| internal_id | Permanent cattle identity |
| tag_number | Current active ear-tag number |
| govt_uid | Government-issued cattle UID |
| prev_tag_numbers | Previous/imported tag references |
| cattle_name | Name of cattle |
| gender | Female or Male |
| category | Cow, Heifer, Bull, Ox, Female Calf, Male Calf, etc. |
| breed | Breed |
| color | Colour |
| dob | Date of birth |
| shed_id | Current shed |
| status | Current lifecycle status |
| adoption_status | Sponsorship/adoption status |
| photo_url | Photo URL |
| is_disabled | Disability flag |
| disability_details | Disability description |
| remarks | General remarks |

### Rules

- `internal_id` must be unique.
- `internal_id` must never change.
- Current active `tag_number` must be unique.
- Historical tags must not replace permanent cattle identity.
- Exited and deactivated cattle remain stored for traceability.

## 15. `samvardhana_outgoing`

### Purpose

Store header, destination, billing, status and audit information for Samvardhana internal transfers and external sales.

### Primary Key

`outgoing_id`

### ID Format

`SVO-######`

Example:

`SVO-000001`

### Columns

| Column | Purpose |
|---|---|
| outgoing_id | Samvardhana transaction ID |
| date | Transaction date |
| movement_type | Internal Transfer or External Sale |
| destination_type | MSGP, Krushi or External Party |
| destination_name | Destination name |
| party_name | External customer |
| receipt_no | Receipt/acknowledgement reference |
| bill_no | External Sale bill number |
| bill_date | Bill date |
| billed_amount | Final billed amount |
| sender_name | Sender |
| receiver_name | Receiver |
| remarks | Transaction remarks |
| status | Completed or Cancelled |
| created_by | Creator |
| created_at | Creation timestamp |
| updated_by | Last updater |
| updated_at | Update timestamp |
| subtotal_amount | Material subtotal |
| tax_amount | Tax snapshot |
| transport_charges | Transport charges |
| other_charges | Other charges |
| other_charges_remarks | Explanation for other charges |
| discount_amount | Discount |

### Movement Rules

#### Internal Transfer

- Destination must be MSGP or Krushi.
- Material lines carry an internal transfer value.
- Billing adjustments and billed amount remain zero.
- Bill number and bill date remain blank.

#### External Sale

- Destination must be External Party.
- Party name is required.
- Bill number is generated automatically.
- Bill date defaults to transaction date.
- Final billed amount is calculated.

### Billing Formula

```text
subtotal_amount
+ tax_amount
+ transport_charges
+ other_charges
- discount_amount
= billed_amount
```

### Validation Rules

- Adjustment values cannot be negative.
- Other Charges Remarks is required when Other Charges is greater than zero.
- Discount cannot exceed subtotal plus charges.
- Billed amount cannot be negative.
- Backend calculation is authoritative.
- Bill number is preserved during Edit.
- Cancelled bill numbers are never reused.
- Cancelled transactions remain stored but are excluded from active reports.

### Bill Number Format

```text
SAM-YYYY-YY-NNNNNN
```

Example:

```text
SAM-2026-27-000001
```

The sequence resets by financial year and is generated while holding an Apps Script lock.

## 20. Reconciliation Relationships

### Milk

```text
milk_production
        |
        v
milk_distribution
        |
        v
samvardhana_outgoing_items
```

- `milk_production` provides total yield.
- `milk_distribution` provides free/internal usage and out-pass information.
- Samvardhana records valued internal transfer or external sale.
- Daily Milk Report reconciles yield, outgoing, good milk, colostrum and free milk.

### Bio-Waste and By-products

```text
bio_waste
        |
        v
samvardhana_outgoing_items
```

- Bio Waste records physical production/movement.
- Samvardhana records valued transfer or external sale.
- Optional source linkage uses `source_type` and `source_transaction_id`.

### Cattle Sales

```text
cattle_master
        |
        v
cattle_exit_log
```

Cattle sales remain in the cattle lifecycle/sales workflow and are not recorded in Samvardhana sheets.

## 21. Audit and Cancellation

- Cancelled records remain stored.
- Cancellation changes status rather than deleting data.
- Cancelled Samvardhana transactions are excluded from active reports and totals.
- Created audit values remain unchanged during Edit.
- Updated audit values reflect the latest modification.
- Generated bill numbers are never reused.
- Item rates and billing values remain historical snapshots.
